# План: изометрический вид графики

Живой список: закрыл фазу — отметь `[x]` и укажи коммит.

## Зачем

Вид сверху показывает полосу 40×22 клетки, а локация в мире больше — половина карты
уходит за экран. Изометрия сворачивает сетку в ромб: та же карта 40×22 проецируется
в 1984×992 и помещается в канвас целиком.

Вид — третий рядом с `graphics` и `ascii`, переключается кнопкой «Вид».

## Ключевые решения

1. **Режим `iso`** третьим, рядом с `graphics`/`ascii`.
2. **Диметрия 2:1.** Тайл на экране 64×32 (`CONFIG.ISO_TILE`), стена — блок 64×64.
3. **Атлас `assets/tiny-dungeon-iso.png`** — полы и стены по стилям и оттенкам,
   генерируется `scripts/generate-tileset.js`. Персонажи, предметы, декор — билборды
   из текущих 16×16 спрайтов.
4. **Глубина = `x + y`**, сортировка всего списка. Герой рисуется последним всегда,
   чтобы стена его не спрятала.
5. **Проекция принадлежит виду.** `js/input.js` больше не считает пиксели сам —
   зовёт `RK.Render.pickTile(px, py)`.

## Формулы

```
sx = (x - y) * TW/2          обратно:  x = (px + 2*py) / TW
sy = (x + y) * TH/2                   y = (2*py - px) / TW
TW = CONFIG.ISO_TILE * zoom * resolutionScale      TH = TW/2
```

При TW=64 проекция карты 40×22 даёт 1984×992 — вся локация влезает в канвас.
ФОV (радиус 7) — ромб 15×15 клеток, он занимает ~960×480 px в центре.

## Фазы

- [x] **Ф1 — Список сцены.** `js/scene.js` собирает items:
  `{kind, x, y, ref, visible, explored, styleId, shade, tile}`. `render.js`
  переводится на «собрать → нарисовать», ASCII-режим — на тот же список.
  *Проверка:* `tests/render-mode.test.js`, `tests/render-zoom.test.js` проходят без правок.
- [x] **Ф2 — Контракт вида.** `js/view.js` задаёт интерфейс:
  `project(x,y)`, `pick(px,py)`, `camera(pos)`, `tileSize()`, `drawItem(...)`.
  `js/view-topdown.js` — перенос текущей отрисовки из `render.js` без изменения результата.
- [x] **Ф3 — Изометрия.** `js/view-iso.js`: ромбы пола, блоки стен, билборды,
  сортировка по `(x+y)`, герой последним, свет эллипсами, оверлеи ромбами.
- [x] **Ф4 — Ввод и эффекты.** `RK.Render.pickTile(px, py)`;
  `RK.Effects.draw(ctx, view)` — позиции эффектов через `view.project`.
- [x] **Ф5 — Режим.** `meta.js` принимает `'iso'`; кнопка «Вид» циклит три режима;
  `ui-help.js` и `README.md` — упоминание.
- [x] **Ф6 — Изо-атлас.** Ячейки 64×64: пол — ромб 64×32 в нижней половине,
  стена — блок во всю ячейку; общий якорь «центр ромба клетки» = (32,48).
  Индексы: 0–4 базовые (floor/wall/floorDim/wallDim/fog), дальше по 3 оттенка
  на стиль из `CONFIG.MAP_STYLES` (8 стилей → 48 ячеек, 53 всего).
  Атлас — 3392×64.
- [x] **Ф7 — Тесты.** Проекция туда-обратно; порядок глубины; режим `iso` рисуется
  без исключений; `pickTile` в обоих видах; `renderMode: 'iso'` переживает
  сохранение/загрузку; покрытие изо-атласа всеми стилями.
- [x] **Ф8 — Поворот камеры.** Угол 0/90/180/270 живёт в `Meta` рядом с зумом,
  кнопки «Поворот влево/вправо» в HUD. Поворачивается только изометрия: у неё
  ромб клетки не меняется, а окно обзора сеточных видов не квадратное.
  Поворот меняет базис проекции (`view-iso.js`): оси сетки ложатся на экран
  иначе, поэтому меняются и экранные координаты клетки, и её глубина.

## Формулы поворота

Оси сетки на экране — знаки `TURNS` в `js/view-iso.js`: `sx1/sy1` — шаг по x,
`sx2/sy2` — шаг по y. Глубина клетки = `sy1 * x + sy2 * y` (больше — ближе),
обратная проекция решается через определитель базиса, поэтому `pick` работает
при любом угле. Ромб клетки и его размер не меняются: поворачивается разложение
сетки, а не сама клетка.

## Риски

| Риск | Что делаем |
|---|---|
| Ф1/Ф2 ломают вид сверху | Существующие тесты ловят порядок вызовов; фазой считаем «тесты зелёные и кадр не изменился» |
| Стены прячут героя | Герой рисуется последним всегда |
| Нет запечённого пола — ромбы каждый кадр | Рисовать только клетки в видимой области; при профилировании — запекание видимого региона |
| Изо-атлас — новый файл ассетов | `assets/README.md` + тест покрытия стилей |
| Нецелые масштабы при зуме 0.25 | Как в текущем виде: `imageSmoothingEnabled = false`, nearest |

## Что не входит

Мобильные устройства, тайлы высоты/этажей, отдельный изо-арт персонажей,
переработка ASCII-режима «с нуля».
