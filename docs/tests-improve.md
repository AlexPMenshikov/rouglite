## Покрытие тестами

Итог: покрытие **функциональное и регрессионное широкое**, но **формального line/branch coverage ещё нет**, но теперь он измерим: harness передаёт `js/*.js` в V8 по абсолютным путям, а команда `npm run test:coverage` запускает встроенный `node --experimental-test-coverage`. Порогов пока нет.

### Цифры
- `npm run lint`: 66 файлов, 0 ошибок.
- Unit: 61 test-файлов, 416 случаев, 0 падений.
- Integration: 15 test-файлов, 121 случай, 0 падений.
- Итого: **76 test-файлов, 537 случаев**, все зелёные.
- Тестируется весь браузерный набор: 58 JS-скриптов загружаются в sandbox (GAME/UI), плюс 4 серверных модуля через интеграционные сценарии.

### Что покрыто хорошо
- Мир/карта: генерация локаций, подземелья/город, декор, вода/ручьи, лимиты карты, восстановление снимков.
- Геймплей: движение, автоклик, FOV, бой, урон, ловушки, ключи/замки, инвентарь, экипировка, предметы, редкости.
- Системы: классы, навыки, заклинания, статусы, голод, кемпинг, события, квесты, диалоги, магазин, кузница, таверна, храм, хранилище, лагерь.
- Город: здания, NPC, торговля/услуги, видимость, storage.
- LAN: rooms, протокол, снимки, реконнект, сейвы, rate limits, статические файлы, multiplayer actions.
- UI/рендер: базовые экраны, настройки, зум, поворот камеры, ASCII/изометрия, help, HUD, storage/quest screens.
- Договорные проверки: `module-surface`, `map-fields`, `config-facts`, `docs-facts`, `melee-kinds`, стабильность экспортов.

### Где покрытие косвенное
Прямые тесты по имени есть у `Pathfind`, `MapCodec`, `ViewTarget`, `CombatMove`, `MapBase`, `MapObjects`, `MapDecor`, `MapGenCity` и `MapGenDungeon`: они проверяют ветки обхода карты, кодека, прицела, шага, базовой сетки, указателей, декора и генерации локаций. Остальные внутренние модули — `CombatRun`, `CombatSnapshot` — по-прежнему проверяются через публичные `RK.Combat`. Это рабочая coverage-by-surface, но не проверка всех внутренних веток.

### Что нашли новые тесты
- `findPathNear` на втором кольце вокруг недостижимой цели возвращал пустой путь и отменял уже найденный шаг к соседней клетке.
- `CombatMove.tryMoveToward` вызывался из клика по дальнему врагу, но не был экспортирован: ближний класс получал `TypeError` вместо шага.

### Основные пробелы
- Встроенный `node --experimental-test-coverage` теперь видит `js/*.js` из-за абсолютных имён файлов, но порогов и baseline в CI пока нет.
- Много веток server-side зависит от поведения, но не измеряется.
- Рендерер проверяется через стаб canvas: пиксельные регрессии не ловятся.
- Стресс сценарии: четырёхгеройный snapshot и повторные круги покрыты, но большие карты, много врагов и долгие асинхронные автоброды — нет.
- Некоторые вспомогательные скрипты (`generate-tileset.js`) не покрыты unit/integration.
- Accessibility и реальные браузерные edge cases не проверяются автоматически.

### Рекомендации
1. Потом добавить `c8`/пороги; базовый отчёт уже можно снимать командой `npm run test:coverage`.
2. Довести прямые тесты до `MapBase`, `MapObjects`, `MapDecor`, `MapGenCity` и `MapGenDungeon`.
3. Добавить нагрузочные тесты для больших карт и большого числа врагов.
4. Зафиксировать минимальные пороги хотя бы для `server/*.js` и `js/combat*.js`.
5. Оставить текущий sandbox-harness подход — он даёт детерминированное покрытие большого battle surface без реального браузера.
