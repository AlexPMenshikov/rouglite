# План технических долгов: сохранение, очистка сессий, размер снимка

Три независимые задачи. Порядок не связан: каждая коммитится отдельно.

Замеры сняты на `createRun` с картой `compact` (48 × 34), 3 локации посещены.

---

## 1. Сохранение забега

### 1.1 Одиночная игра — `js/world.js`

Состояние уже собирается: `createSnapshot()` кладёт `game` + `map` + `world`, а
`applySnapshot()` умеет его разворачивать. Не хватает только записи в
`localStorage` и кнопки продолжения.

| Шаг | Файл | Что |
|---|---|---|
| 1.1.1 | `js/config.js` | `SAVE_KEY = 'rogalite_save_v1'` рядом с `META_KEY` |
| 1.1.2 | `js/world.js` | `saveToStorage()` / `loadFromStorage()` / `clearStorage()` поверх `createSnapshot` и `applySnapshot` |
| 1.1.3 | `js/combat.js` | автосохранение в `finishTurn()` с троттлингом, запись при `travel()` и при смерти героя |
| 1.1.4 | `rougelite.html`, `js/ui.js` | кнопка «Продолжить забег» рядом с «Список комнат», скрыта без снимка |
| 1.1.5 | `js/world.js` | `setState` уже валидирует граф; добавить отказ на битом снимке (нет `map.tiles`, локация не из графа) |

**Решения, которые нужно принять:**

- **Кнопка «Продолжить забег»** — в меню, рядом с «Список комнат»
  (`rougelite.html:25`). Показывается только когда снимок есть и читается.
- **Битый снимок** — не ошибка, а предложение начать заново: кнопка
  «Продолжить» не появляется, «Одиночная игра» работает как обычно. Причина
  в журнал не пишется: игрок ничего не потерял, кроме сохранённого забега.
- **Объём.** Пишем `Combat.createSnapshot()`, а не только `World.getState()`:
  снимок уже самодостаточен, дублировать логику сборки не надо.
- **Троттлинг.** `localStorage.setItem` синхронный. 42 KB на каждом ходу —
  лишний jank. Пишем раз в N ходов (предлагаю 20) и обязательно на переходах
  между локациями и на финале забега.
- **Защита от битых данных.** Снимок из `localStorage` — это ввод пользователя,
  ровно как из сокета. `applySnapshot` уже отвергает неизвестную локацию; нужно
  добавить проверку размеров карты по `MAP_LIMITS`, иначе 10-мегабайтный
  JSON разбирается в браузере и вешает вкладку.
- **Версия снимка.** `SAVE_VERSION` в записи. Формат будет меняться, старые
  снимки должны падать молча, а не ломать загрузку.
- **Класс и герой.** Снимок несёт партию целиком, класс восстанавливается из
  неё. `Meta` трогать не нужно.

### 1.2 Сетевая игра — диск сервера

Комната уже держит полный снимок в `room.state`; на диск его нужно положить
при переходе локации и финале, а не на каждом шаге.

| Шаг | Файл | Что |
|---|---|---|
| 1.2.1 | новый `server/run-store.js` | `saveRoom(code, state)` / `loadRoom(code)` / `deleteRoom(code)`, атомарная запись через `writeFile` + `rename` |
| 1.2.2 | `server/room-manager.js` | `restoreRun(code)` при `joinRoom`: подставить сохранённый снимок в `room.run` и разослать |
| 1.2.3 | `server/game-engine.js` | `createRun({ snapshot })` — собрать забег из готового снимка вместо `newRun` |
| 1.2.4 | `server/room-manager.js` | вызов `saveRoom` при смене локации и при `publish` с `over` |
| 1.2.5 | `server.js`, `.gitignore` | каталог `RUNS_DIR`, по умолчанию `data/runs/` под репозиторием |
| 1.2.6 | `docker-compose.yml` | volume на `data/runs` + переменная окружения, чтобы забеги переживали `docker compose down` |

**Решения, которые нужно принять:**

- **Каталог — `RUNS_DIR`, по умолчанию `data/runs/`.** В Docker файлы внутри
  контейнера исчезают вместе с ним, поэтому compose монтирует том и задаёт
  путь переменной. Одна переменная покрывает оба случая: обычный `npm start`
  ничего не задаёт и пишет рядом с репозиторием.
- **Права в контейнере.** Сервер работает от непривилегированного `nodejs`
  (`Dockerfile:31`), поэтому каталог должен принадлежать uid 1001. В compose
  нужен либо volume с нужным владельцем, либо `RUNS_DIR` на точку, где
  права уже выставлены.
- **`.gitignore`** — `data/` целиком, иначе забеги попадут в коммиты.
- **Ключ файла — код комнаты.** Он уже есть, уникален и не секрет (его видно
  в адресной строке). Отдельный токен хранить не нужно: забег и так доступен
  только по `room.state` внутри протокола.
- **Атомарность.** Писать во временный файл и переименовывать. Иначе падение
  сервера посреди записи оставит нечитаемый JSON, и комната не поднимется.
- **Валидация при чтении.** Файл на диске — тоже недоверенный ввод: те же
  проверки, что на входе из сокета, плюс ограничение размера файла при чтении.
- **Запись только при переходах.** Иначе диск пишется на каждый шаг. Переход
  локации — естественная точка: забег переживает и внезапную смерть, и ход.
- **Секреты.** `player.token` в снимок не попадает (он в `room.players`, не в
  `room.state`). Проверить перед записью.

## 2. Очистка сессий — 20 минут без игроков

Сейчас `removeExpiredRooms()` зовётся только из `createRoom()`: если никто не
создаёт комнату, мёртвые комнаты живут вечно.

| Шаг | Файл | Что |
|---|---|---|
| 2.1 | `server/room-manager.js` | `ROOM_IDLE_MS = 20 * 60 * 1000` рядом с `ROOM_TTL_MS` |
| 2.2 | `server/room-manager.js` | отдельный таймер `startSweeper()` по аналогии с `startHeartbeat()`, `unref()` |
| 2.3 | `server/room-manager.js` | `sweepIdleRooms()`: нет подключённых сокетов И `lastActivity` старше 20 минут → `run.dispose()` + `deleteRoom(code)` |
| 2.4 | `server.js` | `stopSweeper()` в `close()`, как у heartbeat |

**Решения, которые нужно принять:**

- **Условие — «нет подключённых сокетов».** Открытая вкладка без действий
  комнату не убьёт. Иначе игрок отвернётся от экрана и потеряет забег.
  Оговорка: `lastActivity` двигает любое сообщение, поэтому молчащий хост
  держит комнату, пока сокет жив.
- **`ROOM_TTL_MS` (2 часа) оставить** как второй рубеж для комнат с
  подключёнными, но мёртвыми по сокету игроками.
- **Период опроса** — минута. Точность до секунд тут не нужна, а таймер на
  каждой комнате означал бы лишние таймеры в процессе.
- **Забег без игроков.** Если хост ушёл, но забег идёт, комнату всё равно
  сносим: `run.dispose()` освобождает память, а `state` на диске уже сохранён
  (задача 1.2). Порядок вызовов важен — сначала сохранить, потом удалять.

## 3. Уменьшение снимка

Снимок уходит на каждый шаг, поэтому размер умножается на частоту шагов.
Замер: **124 KB** на 3 локации, из них карта текущей — 36 KB.

### 3.1 Убрать `map.vis` — минус 9.8 KB

`js/render.js:877` уже пересчитывает видимость локально для своего героя, а
снимок несёт обзор того, кто ходил. Для клиента это мёртвый груз.

| Шаг | Файл | Что |
|---|---|---|
| 3.1.1 | `js/combat.js` | `createSnapshot()` не кладёт `map.vis` |
| 3.1.2 | `js/combat.js` | `applySnapshot()` восстанавливает `vis` нулевой сеткой того же размера |
| 3.1.3 | проверка | `visibleEnemies()` в `js/combat.js:472` читает `RK.Map.vis` — на сервере поле есть, на клиенте пересчитает `render`. Нужно убедиться, что автопроход клиента не ломается |

**Риск:** `combat.js` читает `RK.Map.vis` в `visibleEnemies()` и
`hasNewVisibleEnemy()`. Если снимок без `vis` придёт на клиент, который сам
ведёт автопроход (сетевой ввод идёт на сервер, но одиночный путь — локальный),
поведение нужно проверить тестом, а не глазом.

### 3.2 RLE для матриц карты

`js/rng.js`-стиль: пара `[значение, длина]` на серию. Обратимость проверена на
всех пяти полях.

| Поле | Было | Стало |
|---|---|---|
| `tiles` | 3.3 KB | 0.9 KB |
| `floorTypes` | 3.3 KB | 1.3 KB |
| `regions` | 3.3 KB | 0.2 KB |
| `explored` | 9.8 KB | 0.5 KB |
| `wallTypes` | 3.3 KB | **оставляем как есть** — см. ниже |

| Шаг | Файл | Что |
|---|---|---|
| 3.2.1 | `js/map.js` | `encodeMatrix(matrix)` / `decodeMatrix(runs, w, h)` рядом с генератором |
| 3.2.2 | `js/combat.js` | кодировать при `createSnapshot`, декодировать в `applySnapshot` |
| 3.2.3 | `js/world.js` | то же для `mapSnapshot` в `visited` |

**Решение по `wallTypes`: оставить.**

Проверено в рендере: `js/render.js:713` красит стену через
`regionStyle.wallColors[mm.wallTypes[y][x]]`, а `bakeFloorLayer` пересобирает
заливку при смене карты или кеш-ключа. Убрать поле из снимок нельзя — на
клиенте стены станут одноцветными. Значения различаются от локации к локации,
потому что `map.js:137` тянет их из RNG генератора.

Кодировать тоже невыгодно: стены чередуются почти на каждой клетке, поэтому
RLE раздувает поле с 3.3 KB до 4.4 KB. Оно едет в снимке как есть.

**Итог 3.1 + 3.2 без кеша статики: 124 KB → 66 KB (46 %).**

### 3.3 Кеш статики локации — минус ещё 23 KB на снимок

Геометрия локации (`tiles`, `floorTypes`, `regions`, `wallTypes`, `rooms`,
`style`, `seed`) не меняется, пока игрок в локации. Слать её на каждом шаге —
чистые повторы.

| Шаг | Файл | Что |
|---|---|---|
| 3.3.1 | `js/combat.js` | снимок несёт `map.static` только при смене локации; иначе — `map.staticRef` с id локации |
| 3.3.2 | `js/world.js` | клиентский кеш `locationId → static`; при отсутствии просит полную карту |
| 3.3.3 | протокол | описать в `docs/lan-protocol.md`: клиент без кеша должен иметь право запросить карту |

**Итог: 66 KB → 43 KB на шаг.** Статика (23 KB) уходит один раз на локацию.

**Риск, из-за которого это отдельный шаг, а не часть 3.2:** кеш вводит
состояние между снимками. Потеря кеша (перезагрузка страницы, новый клиент в
комнате) требует кода восстановления, иначе игрок увидит пустую карту.
Простая альтернатива без кеша: **RLE на геометрию — уже учтено в 3.2.**

### Рекомендуемая граница

Остановиться на **3.1 + 3.2** (46 % экономии, ноль нового состояния между
снимками). 3.3 дать как отдельную задачу, когда упрётся в лимит: там нужен
запрос карты по сети и версия кеша — это уже протокол, а не формат снимка.

| # | Задача | Размер | Зависит |
|---|---|---|---|
| 1 | Очистка сессий (2) | S | — |
| 2 | RLE + vis (3.1 + 3.2) | M | — |
| 3 | Сохранение одиночки (1.1) | M | 2 (меньше писать) |
| 4 | Сохранение сети на диск (1.2) | L | 1 (сначала чистка, чтобы не терять файлы) |

Сначала 2 — он уменьшает и сетевой трафик, и размер сохраняемого состояния,
то есть удешевляет 3 и 4.

## Что потребует уточнения при реализации

- Права на `data/runs/` в контейнере: том в compose должен принадлежать
  uid 1001 непривилегированного пользователя, иначе запись не пройдёт.

## Решено

- `wallTypes` остаётся в снимке как есть: влияет на отрисовку стен, RLE не
  помогает.
- Каталог забегов — `RUNS_DIR`, по умолчанию `data/runs/`; в Docker путь
  задаётся переменной, каталог монтируется томом.
- «Продолжить забег» — кнопка в меню рядом со «Список комнат»; на битом
  снимке её нет, игра начинается заново.
