### Детали задачи 4.0 «Раскрашиваем локации»

Цель: каждая локация видна по цвету, свету и планировке залов, а не по номеру этажа.

- **4.0.1.** `MAP_STYLES[style]` получает `tint` и `light`. `floorDepthTint` (`js/render.js:97`) в режиме локаций берёт тинт стиля (`mm.style`), а в legacy-этажах — прежнюю `FLOOR_PALETTES` по `floor`. Сейчас `floor` в мире всегда `1`, поэтому все локации получают один тинт.
- **4.0.2.** `LOCATION_GEN[type].regionStyles` — список стилей залов, первый совпадает с `gen.style`. `assignRegions` (`js/map.js:820`) выбирает K комнат-стартов по `RK.RNG`, остальные приписывает к ближайшему старту, пишет `room.region` и `g.regionStyles`. Рендер уже читает оба поля.
- **4.0.3.** `regions` жмётся в `MATRIX_FIELDS` и проверяется на `w×h`, а `regionStyles` и `wallTypes` едут сырыми. В `bakeFloorLayer` нужен fallback: неизвестный id → `mm.style`, индекс вне `colors`/`wallColors` → `0`. Тесты в `tests/world.test.js`: длина `regionStyles`, детерминизм по seed, round-trip снимка, битый стиль не роняет рендер.
- **4.0.4.** `rougelite.html:47` знает 3 стиля из 8. Дополнить список — либо прятать селект в режиме локаций.

Ограничения: только `RK.RNG`, без `Math.random` — карту считают и клиент, и сервер. Снимок не растёт: `regions` уже в кодеках, `regionStyles` — короткий массив строк. Строки интерфейса и доков — по-русски.
