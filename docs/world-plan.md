# План: Мир с локациями (Location-based World)

## Видение
**Локации с переходами** — города, дикая природа, данжи как отдельные сцены с загрузкой.
Приоритет: **исследование**. Масштаб: **эволюция текущего кода**.

---

## Архитектура
> **Локация = сцена с профилем MapGen + системами (NPC, квесты, спавн, правила перехода).**
> Мир = граф локаций. Игрок перемещается по рёбрам (пути, порталы, двери).

### Детали задачи 4.0 «Раскрашиваем локации»

Цель: каждая локация видна по цвету, свету и планировке залов, а не по номеру этажа.

Осталось:

- **4.0.3.** ✅ `bakeFloorLayer` откатывает неизвестный стиль зала к `mm.style`, а индекс палитры вне `colors`/`wallColors` — к нулевому цвету. Регресс-тест в `tests/render-mode.test.js`.
- **4.0.4.** ✅ Селект оформления знает все 8 стилей из `MAP_STYLES`.

Ограничения: без `Math.random` — карту считают и клиент, и сервер. Старты залов берёт `seededRandom` по seed карты, а не `RK.RNG`: иначе при том же seed сдвинулись бы позиции врагов, предметов и сундуков. Снимок не растёт: `regions` уже в кодеках, `regionStyles` — короткий массив строк. Строки интерфейса и доков — по-русски.

### Детали задачи 4.1 «Элитные/чемпионы»
Цель: чемпион отличается до боя, меняет бой и поведение, но не ломает серверный снимок и мультиплеер.
- **4.1.1.** Поля `isChampion`, `affixes`, `phase`, `phaseDone` у врага. Шанс спавна `RK.RNG.chance`, без `Math.random`; чемпионы не получают статус босса.
- **4.1.2.** Каталог аффиксов в `RK.Entities`: множители HP/ATK/DEF, особые свойства (сопротивление, вампиризм, ускорение, взрыв при смерти), названия.
- **4.1.3.** Применение аффиксов в существующих местах урона: `playerAttackDamage`, `enemyAttackDamage`, `finishTurn`, `killEnemy`. Новые `if byPlayer`-ветвления не вводить.
- **4.1.4.** Фазы срабатывают один раз при пороге HP: смена атаки/поведения, лечение, призыв подкрепления. Боссов можно перевести на ту же схему.
- **4.1.5.** Цвет/масштаб/имя чемпиона, повышенные XP/золото/лут, сообщение и показ аффикса. Рендер и UI читают только сериализуемые свойства.
- **4.1.6.** Поля чемпиона едут врагом целиком. Тесты: детерминизм спавна по seed, round-trip снимка, фаза срабатывает один раз.

Ограничения: чемпионы не должны ломать `enhanced`, боссов и старые тесты (`location-enemies`, `game-loop`).

### Детали задачи 4.2 «Статус-эффекты и стихии»
Цель: заменить разрозненные поля единым статусным механизмом и ввести типы урона.
- **4.2.1.** `RK.Statuses` с определениями и функциями `apply`, `tick`, `remove`; данные на `player.statuses`/`enemy.statuses` с fallback к текущим полям во время миграции.
- **4.2.2.** Один тик-проход по партии и врагам в `finishTurn`; без повторного урона на том же ходу через `appliedTurn`.
- **4.2.3.** Горение, яд, холод на базе статуса; `burning*` заменяются постепенно, тесты горения сохраняются.
- **4.2.4.** Оглушение/замедление/лишение хода через статус; `e.stunned` остаётся bridge на время перехода.
- **4.2.5.** `damageType` для оружия/ловушек/стихий, резисты и уязвимости. Начальная таблица небольшая.
- **4.2.6.** Источники: огненная ловушка, атаки, зоны, аффиксы чемпионов. Новые ветки не дублировать.
- **4.2.7.** UI показывает статусы и оставшееся время; визуал только в `effects.js`; компактный снимок и тесты.

Зависимость: аффиксы 4.1, дающие статус, начинать после 4.2.1 и 4.2.3.
