# Рогалик

Браузерный roguelite с процедурными подземельями, тремя классами и LAN-кооперативом до 4 игроков. Одиночная игра запускается прямо в браузере; для сетевой игры нужен Node.js 18+.

## Возможности

- Процедурные этажи: каменные залы, пещеры и склепы; размеры карт от 32×23 до 96×68.
- Танк, берсерк и лучник — разные характеристики и классовые навыки.
- Враги, боссы, уровни, ловушки, сундуки, предметы, экипировка и зелья.
- Инвентарь с сортировкой и фильтрами; постоянные улучшения, банк золота, торговец с заданиями и кузнец.
- Автопроход по клику и плавное анимированное движение всей партии, а не только своего героя.
- Слева от карты — журнал боя: его можно свернуть в узкую полосу; HP, золото, опыт и ключи вынесены в окно персонажа.
- Кнопки помечены пиксельными иконками из движка — по логике действия, а не украшением.
- Таверна, озерца и ручьи; ASCII- и пиксельный режимы.
- LAN-кооператив до 4 игроков: забег ведёт сервер, поэтому свёрнутое окно хоста не мешает остальным ходить; отключившиеся игроки могут переподключиться. В меню видно список комнат на сервере с игроками в каждой. Комнаты хранятся в памяти сервера и теряются при его перезапуске.
- Прогресс одиночной игры и настройки сохраняются в браузере.

## Запуск

**Одиночная игра:** откройте `rougelite.html` в современном браузере, укажите имя и нажмите «Играть».

**LAN-игра:** установите Node.js 18+, затем на компьютере с сервером запустите `start.bat` (Windows) или `./start.sh` (Linux/macOS). Один игрок нажимает «Создать комнату» и сообщает код остальным: они открывают адрес из консоли, жмут «Список комнат» и подключаются к нужной кнопкой либо вводят код вручную. Если скрипт не может найти зависимость `ws`, он установит её через npm.

**Разработка и тесты:**

```sh
npm install
npm start       # LAN-сервер; порт задаётся через PORT, по умолчанию выбирается автоматически
npm test        # проверка синтаксиса + все тесты
npm run lint         # разбор игровых скриптов и файлов сервера без запуска игры
npm run test:unit         # быстрые unit-тесты игровых систем
npm run test:integration  # LAN-сервер и сетевой рендеринг
```

## Структура проекта

- `rougelite.html`, `css/style.css` — интерфейс и стили; игровые скрипты подключены в HTML в порядке зависимостей.
- `js/` — логика игры: генерация карты, сущности, предметы, классы, бой, рендеринг, UI и сеть.
- `js/config.js` — конфигурация: размеры карт, цвета, боевые константы и таблицы предметов, слотов, ловушек и зон. Файл подключается и как `<script>`, и как CommonJS-модуль: сервер берёт оттуда пределы карты и слоты экипировки, поэтому валидация не расходится с клиентом.
- `js/debug.js` — комната отладки: одна фикстура со всеми объектами игры, отдельно от боевой логики.
- `server.js`, `server/` — HTTP/WebSocket-сервер, управление LAN-комнатами и игровая логика забега. Один и тот же движок работает в браузере и в Node: `server/game-engine.js` поднимает те же скрипты из `js/` в `node:vm` без правок под сервер.
- `tests/` — unit- и интеграционные тесты на встроенном `node:test`; общий харнес в `tests/helpers/sandbox.js` поднимает игру в `node:vm` с минимальным DOM. CI проверяет синтаксис и гоняет тесты на Node 18, 20 и 22.
- `scripts/check-syntax.js` — разбор всех скриптов из `rougelite.html` и файлов сервера: без сборщика опечатка иначе видна только в браузере.
- `assets/` — графические ресурсы; описание форматов — в [`assets/README.md`](assets/README.md). Пиксельные иконки кнопок не файлы, а код: они рисуются в `buildUiIcons()` в `js/assets.js`, список имён — `UI_ICON_SPRITES`.

Сборка пока не нужна: браузер загружает обычные скрипты напрямую. Список файлов и порядок подключения находятся внизу `rougelite.html`; переход к ES-модулям/сборщику имеет смысл при росте приложения или появлении внешних frontend-зависимостей.

## Изменения игры и тесты

- **Новый класс:** добавьте описание и поведение в `js/classes.js`, синхронизируйте разблокировку/стоимость в `js/meta.js` и интерфейс в `js/ui.js`. Проверьте характеристики, навык и ограничения экипировки тестами в `tests/`.
- **Новый предмет:** добавьте генерацию/поля в `js/items.js`, при необходимости отображение в `js/assets.js` и `js/render.js`, а также использование в `js/combat.js`. Проверьте генерацию, подбор и применение.
- **Новая кнопка:** добавьте спрайт в `buildUiIcons()` и его имя в `UI_ICON_SPRITES` в `js/assets.js`, затем укажите кнопку в `STATIC_BUTTON_ICONS` (`js/ui.js`) или соберите её через `makeButton(иконка, подпись)`. Иконки рисуются после загрузки спрайтов, поэтому новую кнопку достаточно перечислить в таблице.
- **Новый слот, редкость, тип ловушки или зоны:** правится одна таблица в `js/config.js` — остальной код (UI, сервер, валидация) подхватывает её сам.
- **Новый тест:** добавьте `tests/<feature>.test.js`, включите его в соответствующую команду `test:unit` или `test:integration` в `package.json` и используйте общий харнес из `tests/helpers/sandbox.js` вместо собственного DOM-стаба. Запускайте отдельно через `node --test tests/<feature>.test.js` и перед отправкой — `npm test`.
- **Новое LAN-действие или изменение снимка:** обновите клиент, правило в `ACTION_RULES` (`server/room-manager.js`) и таблицу обработчиков в `js/combat.js`; сверяйтесь с [`docs/lan-protocol.md`](docs/lan-protocol.md) и добавьте интеграционные проверки.
- **Движение и анимация партии:** шаг хранится на каждого участника в `walk.steps` (`js/combat.js`); `busy()` смотрит только на героя текущего клиента, `tickWalk()` двигает все шаги и считает завершённые через `stepsDone()`, а сервер по этому счётчику публикует снимок на шаг. Правила автопрохода закреплены в `tests/player-movement.test.js`.

## Управление

| Действие | Управление |
|---|---|
| Движение | WASD, стрелки или нумпад |
| Автопроход по клетке | клик мышью по полу |
| Шаг к врагу / выстрел лучника | клик мышью по врагу в пределах видимости |
| Взаимодействие с дверью, сундуком или NPC | `E` |
| Взлом замка / обезвреживание ловушки | `L` |
| Выбить / сломать | `F` |
| Зелье / классовый навык | `R` / `Q` |
| Пропустить ход | `5` или `.` |
| Выход из комнаты отладки | `Esc` |

Для взаимодействия с объектом или торговцем встаньте рядом и повернитесь к нему. В игре также доступны кнопки управления и справка.

Клик по полу — это автопроход: герой идёт до клетки самым коротким путём, а шаг всех участников партии анимируется. Маршрут прерывается, если в поле зрения появился новый враг (уже видимые к моменту клика враги маршрут не отменяют), путь перекрыт или герой погиб на ходу.

## Графические ресурсы

Игра использует PNG-тайлсеты 16×16. Порядок тайлов задаётся через `KENNEY_MAP` в `js/assets.js`; кастомные полы и стены `floor-dark.png` / `wall-dark.png` применяются на этажах 4–6, `floor-deep.png` / `wall-deep.png` — на этажах 7–10. Если файл или тайл отсутствует, используются встроенные текстуры. Проверяйте лицензию ресурсов перед распространением; сведения о форматах и лицензиях — в [`assets/README.md`](assets/README.md).
