# Рогалик

Браузерный roguelite с процедурным миром локаций и LAN-кооперативом до 6 игроков. Одиночная игра — прямо в браузере; для сетевой нужен Node.js 18+.

## Возможности

- Мир локаций: город Арген, лес, болото, горы, пустыня и оазис соединены переходами; под каждой локацией — подземелье до 4 ярусов. Карты от 32×23 до 96×68.
- Паладин, берсерк, лучник, маг — разные характеристики, оружие и навыки.
- Враги, боссы, чемпионы с аффиксами и фазами, ловушки, сундуки, предметы, экипировка, зелья.
- Статусы и стихии: горение, яд, кровотечение, холод, оглушение, резисты и уязвимости.
- Инвентарь с сортировкой и фильтрами; постоянные улучшения, банк золота, торговец с заданиями, кузнец.
- Автопроход по клику, анимированное движение всей партии.
- Журнал боя — на экране настроек; HP, золото, опыт и ключи — в окне персонажа, там же кнопки способностей.
- Пиксельные иконки кнопок рисуются движком — по логике действия.
- Таверна, озерца, ручьи; три вида показа: пиксельный, ASCII и изометрия.
- В изометрии камеру можно поворачивать на 90° кнопками «Поворот влево/вправо»: вид и зум сохраняются между запусками.
- LAN-кооператив до 6 игроков: забег ведёт сервер, поэтому свёрнутое окно хоста не мешает остальным ходить; отключившиеся игроки могут переподключиться. Список комнат с игроками — в меню. Список комнат живёт в памяти сервера, а забег ложится на диск: перезапуск сервера не сбрасывает забег, и игрок возвращается по токену.
- Прогресс одиночной игры и настройки — в браузере.

## Запуск

**Одиночная игра:** откройте `rougelite.html` в современном браузере, укажите имя, нажмите «Играть».

**LAN-игра:** нужен Node.js 18+. На компьютере с сервером — `start.bat` (Windows) или `./start.sh` (Linux/macOS). Один игрок жмёт «Создать комнату» и сообщает код остальным: они открывают адрес из консоли, видят комнату в «Список комнат» и подключаются кнопкой либо вводят код вручную. Если не найдена зависимость `ws`, скрипт установит её через npm.

**Разработка и тесты:**

```sh
npm install
npm start            # LAN-сервер; порт задаётся через PORT, иначе выбирается автоматически
npm test             # синтаксис + все тесты
npm run lint         # разбор скриптов без запуска игры
npm run test:unit    # unit-тесты игровых систем
npm run test:integration  # LAN-сервер и сетевой рендеринг
```

## Структура проекта

- `rougelite.html`, `css/style.css` — интерфейс и стили; скрипты подключены в HTML в порядке зависимостей.
- `js/` — логика: карта, сущности, предметы, классы, бой, рендеринг, UI, сеть.
- `js/config.js` — конфигурация: размеры карт, цвета, боевые константы, таблицы предметов, слотов, ловушек, зон. Подключается и как `<script>`, и как CommonJS-модуль: сервер берёт оттуда пределы карты и слоты, поэтому валидация не расходится с клиентом.
- `js/debug.js` — комната отладки: одна фикстура со всеми объектами, отдельно от боевой логики.
- `server.js`, `server/` — HTTP/WebSocket-сервер, LAN-комнаты и логика забега. Движок тот же, что в браузере: `server/game-engine.js` поднимает те же скрипты из `js/` в `node:vm` без правок.
- `tests/` — unit- и интеграционные тесты на `node:test`; общий харнес в `tests/helpers/sandbox.js` поднимает игру в `node:vm` с минимальным DOM. CI — Node 20, 22 (движок требует Node 18+).
- `scripts/check-syntax.js` — разбор всех скриптов и сервера: без сборщика опечатка иначе видна только в браузере.
- `assets/` — ресурсы; форматы — в [`assets/README.md`](assets/README.md). Иконки кнопок — не файлы, а код: рисуются в `buildUiIcons()` (`js/assets.js`), имена — `UI_ICON_SPRITES`.

Сборка не нужна: браузер загружает скрипты напрямую. Список скриптов и их порядок — в `scripts/script-list.js`, страница ему следует, и `npm run lint` падает при расхождении. Переход на ES-модули/сборщик имеет смысл при росте приложения.

## Изменения и тесты

- **Класс:** описание и поведение в `js/classes.js`, разблокировка/стоимость в `js/meta.js`, интерфейс в `js/ui-*.js`; проверьте характеристики, навык и ограничения экипировки тестами.
- **Предмет:** генерация/поля в `js/items.js`, отображение в `js/assets.js` и `js/render.js`, использование — в `js/inventory.js` и `js/spells.js`; проверьте генерацию, подбор, применение.
- **Кнопка:** спрайт в `buildUiIcons()`, имя в `UI_ICON_SPRITES` (`js/assets.js`), затем — в `STATIC_BUTTON_ICONS` (`js/ui-core.js`) или через `makeButton(иконка, подпись)`.
- **Слот, редкость, ловушка, зона:** правится одна таблица в `js/config.js` — остальной код (UI, сервер, валидация) подхватывает сам.
- **Тест:** файл `tests/<feature>.test.js`; категория выводится из имени (`scripts/run-tests.js`), поэтому новый тест не требует правки списков. Харнес — из `tests/helpers/sandbox.js`, не свой DOM-стаб. Запуск одного файла — `node --test tests/<feature>.test.js`, всех сразу — `npm test`.
- **LAN-действие или снимок:** клиент, правило в `ACTION_RULES` (`server/room-manager.js`), обработчики в `js/combat.js`; сверяйтесь с [`docs/lan-protocol.md`](docs/lan-protocol.md), добавьте интеграционные проверки.
- **Движение и анимация:** шаг хранится на участника в `walk.steps` (`js/combat-move.js`); `busy()` смотрит только на локального героя, `tickWalk()` двигает все шаги и считает завершённые через `stepsDone()`, сервер публикует снимок на шаг. Правила автопрохода — в `tests/player-movement.test.js`.

## Управление и справка

Клавиши, роза восьми направлений, правила автопрохода, состав классов и вход в сетевую игру описаны в игровой справке — кнопка «Справка» в интерфейсе. Здесь дублировать её не нужно: два списка клавиш расходятся, как только меняется одна из сторон.

## Графические ресурсы

PNG-тайлсеты 16×16; порядок — `KENNEY_MAP` в `js/assets.js`; если файла или тайла нет — встроенные текстуры. Кастомные полы/стены `floor-dark.png` / `wall-dark.png` — с 4-го этажа, `floor-deep.png` / `wall-deep.png` — с 7-го. Глубина данжа сейчас 4 (`CONFIG.DUNGEON_MAX_DEPTH`), поэтому набор `deep` в игре не встречается — он остался от прежних десяти этажей. Проверяйте лицензию перед распространением; форматы и лицензии — в [`assets/README.md`](assets/README.md).

### Hi-res тайлы 256×256 (и любой другой размер)

Для каждого спрайта можно положить отдельный PNG-файл в `assets/sprites/<name>.png` — квадрат любого размера. Также поддерживается путь `assets/<name>.png` (на случай, если файл лежит в корне папки `assets`): сначала проверяется `assets/sprites/`, затем `assets/`. Движок автоматически подберёт его при загрузке с приоритетом:

1. Если есть `assets/sprites/<name>.png` — используется он (в нативном размере; сглаживание — только при уменьшении, иначе пиксели резкие).
2. Иначе — тайл из 16×16-атласа (`tiny-dungeon.png` / `spritesheet.png`).
3. Иначе — встроенный 16×16-спрайт.

Частичная замена допустима: заменить можно один или несколько спрайтов, остальные подтянутся встроенные/из атласа. Имена файлов совпадают с именами спрайтов в коде: `sword`, `axe`, `spear`, `bow`, `crossbow`, `shield`, `shieldSmall`, `shieldLarge`, `boots`, `head`, `helmet`, `armor`, `ring`, `amulet`, `key`, `potion`, `player`, `torch`, `trapSpike`, `trapNeedle`, `trapFlame` и т.д., а также иконки UI (`uiPlay`, `uiBack` … `uiCamp`). Имена встроенного набора — `RK.Assets.builtinFallbackNames()`. Переключатель `tileset-enabled` не трогаем — hi-res включается автоматически при наличии файла.

### Тайлы героя для классов

Тайлы героя различаются по классу: `playerPaladin`, `playerBerserker`, `playerArcher`, `playerMage` (и базовый `player` как запасной). Положите PNG в `assets/sprites/playerPaladin.png` (или `assets/playerPaladin.png`) — и паладин будет выглядеть иначе, аналогично для берсерка, лучника и мага. При отсутствии файла используется базовый `player`.
