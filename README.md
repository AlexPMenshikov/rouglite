# Рогалик

Браузерный roguelite с процедурными подземельями, тремя классами и LAN-кооперативом до 4 игроков. Одиночная игра — прямо в браузере; для сетевой нужен Node.js 18+.

## Возможности

- Процедурные этажи: каменные залы, пещеры и склепы; карты от 32×23 до 96×68.
- Танк, берсерк, лучник — разные характеристики и навыки.
- Враги, боссы, ловушки, сундуки, предметы, экипировка, зелья.
- Инвентарь с сортировкой и фильтрами; постоянные улучшения, банк золота, торговец с заданиями, кузнец.
- Автопроход по клику, анимированное движение всей партии.
- Слева от карты — журнал боя: сворачивается в узкую полосу, не уменьшая поле; HP, золото, опыт и ключи — в окне персонажа.
- Пиксельные иконки кнопок рисуются движком — по логике действия.
- Таверна, озерца, ручьи; ASCII- и пиксельный режимы.
- LAN-кооператив до 4 игроков: забег ведёт сервер, поэтому свёрнутое окно хоста не мешает остальным ходить; отключившиеся игроки могут переподключиться. Список комнат с игроками — в меню. Комнаты в памяти сервера, теряются при перезапуске.
- Прогресс одиночной игры и настройки — в браузере.

## Запуск

**Одиночная игра:** откройте `rougelite.html` в современном браузере, укажите имя, нажмите «Играть».

**LAN-игра:** нужен Node.js 18+. На компьютере с сервером — `start.bat` (Windows) или `./start.sh` (Linux/macOS). Один игрок жмёт «Создать комнату» и сообщает код остальным: они открывают адрес из консоли, видят комнату в «Список комнат» и подключаются кнопкой либо вводят код вручную. Если не найдена зависимость `ws`, скрипт установит её через npm.

**Разработка и тесты:**

```sh
npm install
npm start            # LAN-сервер; порт задаётся через PORT, иначе выбирается автоматически
npm test             # синтаксис + все тесты
npm run lint         # разбор скриптов без запуска игры
npm run test:unit    # unit-тесты игровых систем
npm run test:integration  # LAN-сервер и сетевой рендеринг
```

## Структура проекта

- `rougelite.html`, `css/style.css` — интерфейс и стили; скрипты подключены в HTML в порядке зависимостей.
- `js/` — логика: карта, сущности, предметы, классы, бой, рендеринг, UI, сеть.
- `js/config.js` — конфигурация: размеры карт, цвета, боевые константы, таблицы предметов, слотов, ловушек, зон. Подключается и как `<script>`, и как CommonJS-модуль: сервер берёт оттуда пределы карты и слоты, поэтому валидация не расходится с клиентом.
- `js/debug.js` — комната отладки: одна фикстура со всеми объектами, отдельно от боевой логики.
- `server.js`, `server/` — HTTP/WebSocket-сервер, LAN-комнаты и логика забега. Движок тот же, что в браузере: `server/game-engine.js` поднимает те же скрипты из `js/` в `node:vm` без правок.
- `tests/` — unit- и интеграционные тесты на `node:test`; общий харнес в `tests/helpers/sandbox.js` поднимает игру в `node:vm` с минимальным DOM. CI — Node 18, 20, 22.
- `scripts/check-syntax.js` — разбор всех скриптов и сервера: без сборщика опечатка иначе видна только в браузере.
- `assets/` — ресурсы; форматы — в [`assets/README.md`](assets/README.md). Иконки кнопок — не файлы, а код: рисуются в `buildUiIcons()` (`js/assets.js`), имена — `UI_ICON_SPRITES`.

Сборка не нужна: браузер загружает скрипты напрямую, список и порядок — внизу `rougelite.html`. Переход на ES-модули/сборщик имеет смысл при росте приложения.

## Изменения и тесты

- **Класс:** описание и поведение в `js/classes.js`, разблокировка/стоимость в `js/meta.js`, интерфейс в `js/ui.js`; проверьте характеристики, навык и ограничения экипировки тестами.
- **Предмет:** генерация/поля в `js/items.js`, отображение в `js/assets.js` и `js/render.js`, использование в `js/combat.js`; проверьте генерацию, подбор, применение.
- **Кнопка:** спрайт в `buildUiIcons()`, имя в `UI_ICON_SPRITES` (`js/assets.js`), затем — в `STATIC_BUTTON_ICONS` (`js/ui.js`) или через `makeButton(иконка, подпись)`.
- **Слот, редкость, ловушка, зона:** правится одна таблица в `js/config.js` — остальной код (UI, сервер, валидация) подхватывает сам.
- **Тест:** `tests/<feature>.test.js` + команда `test:unit` или `test:integration` в `package.json`; харнес — из `tests/helpers/sandbox.js`, не свой DOM-стаб. Запуск одного файла — `node --test tests/<feature>.test.js`.
- **LAN-действие или снимок:** клиент, правило в `ACTION_RULES` (`server/room-manager.js`), обработчики в `js/combat.js`; сверяйтесь с [`docs/lan-protocol.md`](docs/lan-protocol.md), добавьте интеграционные проверки.
- **Движение и анимация:** шаг хранится на участника в `walk.steps` (`js/combat.js`); `busy()` смотрит только на локального героя, `tickWalk()` двигает все шаги и считает завершённые через `stepsDone()`, сервер публикует снимок на шаг. Правила автопрохода — в `tests/player-movement.test.js`.

## Управление

| Действие | Управление |
|---|---|
| Движение | WASD, стрелки или нумпад |
| Автопроход по клетке | клик по полу |
| Шаг к врагу / выстрел лучника | клик по врагу в пределах видимости |
| Телепорт в город | кнопка «Телепорт в город» вне города |
| Взаимодействие с дверью, сундуком, NPC | `E` |
| Взлом замка / ловушки | `L` |
| Выбить / сломать | `F` |
| Зелье / навык | `R` / `Q` |
| Пропустить ход | `5` или `.` |
| Выход из комнаты отладки | `Esc` |

Для взаимодействия с объектом или торговцем встаньте рядом и повернитесь к нему. В игре есть кнопки управления и справка.

Клик по полу — автопроход: герой идёт кратчайшим путём, шаг партии анимируется. Маршрут прерывается, если в поле зрения появился новый враг (уже видимые к клику не отменяют), путь перекрыт или герой погиб на ходу.

## Графические ресурсы

PNG-тайлсеты 16×16; порядок — `KENNEY_MAP` в `js/assets.js`; если файла или тайла нет — встроенные текстуры. Кастомные полы/стены `floor-dark.png` / `wall-dark.png` — этажи 4–6, `floor-deep.png` / `wall-deep.png` — этажи 7–10. Проверяйте лицензию перед распространением; форматы и лицензии — в [`assets/README.md`](assets/README.md).
